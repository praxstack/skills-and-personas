# Theatre.js guide

Theatre.js is the animation system: every moving value in the film is a prop on a Theatre sheet object, and
every keyframe is generated from the voice timing by a script. The default picture is a 2.5D layered DOM/SVG
stage (parallax depth layers, a Theatre camera, depth of field) captured frame by frame by `capture.mjs`.

## 1. Setup

```bash
mkdir -p source && cp -r $SKILL/assets/template/. source/ && (cd source && npm ci --no-audit --no-fund)
```

Pinned (package.json, exact): `@theatre/core 0.7.2`, `esbuild 0.28.2`, `inter-ui 4.1.1` (Inter variable),
`jetbrains-mono 1.0.6` (the NL files: no ligatures), `@fontsource/bangers 5.3.0` (comic bursts), `playwright-core 1.56.1` (capture). About 33 MB of
node_modules, 9 packages; `npm ci` takes about 1.5 s from the npm cache, a few seconds cold. `npm run build`
takes about 0.3 s. Optional, never needed to render: `@theatre/studio 0.7.2` (section 9), `three 0.186.1`
(section 10). Capture uses the template's `playwright-core` 1.56.1 (a devDependency, installed by `npm ci`) and the Chromium in
`/opt/pw-browsers` (found automatically; on a laptop, `npx playwright install chromium` inside `source/`).
No environment variables are needed here; `CHROMIUM=/path/to/chrome` overrides the browser.

## 2. Project anatomy

```
source/
  timing.js            written by voice.py --emit source/timing.js (window.TIMING = {...}; never edit)
  index.html           the film page: dist/film.css, timing.js, dist/film.js
  theatre-state.json   GENERATED by npm run build from timing.js + shots.js (Theatre project state)
  src/film/world.js    WHAT is in the film: the kit components and their data (graph, code, tables...)
  src/film/shots.js    WHEN things happen: every keyframe, keyed to line ids
  src/kit/*.js         the reusable pieces (section 6); tokens.js = palette, moods, fonts, sizes
  src/kit/style.css    all CSS (reads tokens as CSS variables)
  src/theatre/keys.js  the compiler: shot list -> Theatre keyframes (bezier handles, holds)
  src/theatre/rig.js   getProject(id, {state}), sheet objects, values(t)
  src/theatre/timing.js T helpers (section 4);  recipes.js  R helpers (section 7)
  src/main.js          boots the page, loads fonts, implements the capture contract
  tools/build.mjs      npm run build: state + bundle (+ --3d, --studio); prints the coverage report
  tools/studio-diff.mjs  what a Studio export changed (section 9)
  studio.html, src/studio.js     optional Studio page;  index-3d.html, src/variants/three.js  3D variant
```

A new film rewrites `world.js` and `shots.js`; it touches the kit only to add a component (section 6, last
paragraph). Mount order in `world.js` is paint order inside a layer.

## 3. How a frame is made

1. `npm run build` imports `world.js` and `shots.js` in node, runs `shots(s, T, W)` and compiles every call
   into `BasicKeyframedTrack` keyframes: the same JSON `@theatre/studio` exports. It writes
   `theatre-state.json` (stamped with the timing hash) and bundles `dist/film.js`. Files are written only
   when their bytes change, so a resumed render is not restarted by a no-op build.
2. The page loads `timing.js`, then `getProject('Explainer', { state })`, creates one sheet object per kit
   object, and awaits `project.ready`.
3. `window.renderFrame(t)` sets `sheet.sequence.position = t`, reads every object's `.value` (synchronous and
   deterministic; no playback, no clock), and each component writes only the DOM/SVG attributes that changed.
4. `capture.mjs` screenshots each frame. `window.TOTAL = TIMING.total` exactly.

If `theatre-state.json` is missing or was built for another timing hash, the page compiles the shots itself
(console warning), so a re-voice can never play stale keyframes. `index.html?state=other.json` plays a
Studio export instead. `?t=31.5` shows one frame, `?debug=1` draws the safe area, time and line id, `?play=1`
plays in real time with `../voice/narration.wav` (click to start).

The build prints a coverage report. Act on it: `NOTHING changes during lines: ...` breaks the quality bar;
`only the camera moves during lines: ...` usually should get a visible change; `warning: ... interrupts` means
two tweens on one prop overlap (the earlier one is cut where the later starts; usually fine, often a typo).

## 4. Timing API

`T = timeline(window.TIMING)` (src/theatre/timing.js). Every time in `shots.js` comes from here.

| Call | Returns |
|---|---|
| `T.at(id, frac=0)` | when the voice of line `id` starts, or `frac` of the way through its spoken words |
| `T.after(id, sec=0)` | `sec` after the voice of `id` ends (think pauses start here) |
| `T.start(id, sec=0)` / `T.end(id, sec=0)` | the line's whole slot (lead-in, voice, pad, think), plus `sec` |
| `T.dur(id)` | how long the voice of `id` speaks |
| `T.word(id, 'seven hundred')` | when that phrase is spoken (estimated from its position in `say`; throws if absent) |
| `T.think(id)` | `{ t, dur }` of the silent pause after a question |
| `T.chapter(n)` | `{ n, name, start, end }`; `T.chapters` lists them |
| `T.line(id)` | the timing entry (`cap`, `say`, `voiceAt`, `voiceDur`, `think`...); throws listing known ids |
| `T.lineAt(t)`, `T.chapterAt(t)`, `T.has(id)` | lookups; `T.total`, `T.fps`, `T.title`, `T.hash` |

Anchor to the words: `T.word('c1', 'round one')` puts the edge fire on the word; `T.at('p3', 0.45)` is a fine
fallback. Never type seconds.

## 5. Shot builder

`shots(s, T, W)` in `src/film/shots.js`. Object keys are the Theatre object names (`'Camera'`, `'Code'`,
`G.nodeKey(1)`, `G.edgeKey(0, 1)`); props are checked against the component's `objects()` defaults, and a typo
fails the build with the list of valid names.

| Call | Does |
|---|---|
| `s.set(obj, {p: v}, t)` | jump at t and hold (text, line ids, steps, booleans) |
| `s.to(obj, {p: v}, t, dur=0.6, ease='inOut')` | tween from the value held at t (strings/booleans become a set) |
| `s.fromTo(obj, from, to, t, dur, ease)` | set `from` at t, tween to `to` (rings, fires: replays from 0) |
| `s.pulse(obj, prop, t, {peak, base, up, hold, down})` | up to peak and back (glow, flash, shake) |
| `s.stagger([objs], props, t, dur, gap, ease='back')` | the same tween `gap` s apart (nodes popping in) |
| `s.cam(props, t, dur, ease)` | raw Camera tween; prefer `R.focus` |

Eases (`keys.js` EASE, CSS cubic-bezier): `linear in out inOut soft expoOut expoInOut back backIn snap`, or
pass `[x1, y1, x2, y2]`. Colours on rgba props take `'#rrggbb'`. Before its first keyframe a prop holds its
default from `objects()`; the compiler adds that keyframe at 0 so Theatre does not show the first tween's value.

## 6. Kit catalogue

Each component is a class with `objects()` (its Theatre objects and defaults), `mount(stage)` (DOM, once) and
`apply(V, t)` (per frame). Panels also have `rect()` (layer px) for camera framing.

| Component (world.js) | Theatre object: props |
|---|---|
| `new Stage({ backdrop: 'skyline', floor: true, grain: 'still' })` | `Camera`: x, y (pan), z (dolly in, px), orbit, tilt, roll (deg), dof (0..1 background blur), scrim (darken subject), drift (handheld float), shake. `Sky`: top, bottom, glow (rgba), glowY, city. `Content`: in (fades subject, panels and HUD together; R.chapter drives it) |
| `new Graph({ nodes:[{id,x,y,badgeAt?}], edges:[{from,to,w,bend}], tokens })` | `Graph`: x, y, s, in. `Graph / node <id>`: in, glow, hot, good, bad, dim, ring, tag, tagIn, badge, badgeIn, badgeAt ('tr' \| 'tl' \| 'br' \| 'bl' \| 'above' \| 'below'; '' falls back to the node's data, then 'tr'; `s.set` it per shot to keep a badge clear of a chip or panel). `Graph / edge a-b`: draw, glow, hot, good, bad, dim, fire, strike, label. `Graph / token i`: route ("0-1-3"), u, in, sum (a token leaves from the first node's rim and docks at the last arrowhead, so it never covers a node's number) |
| `new Decoder({ graph, x, y, rows:[{text, chip?, to:{edge:'0-1'}\|{node:0}}] })` | `Decoder`: in, rows, hl, dim, x, y. `Decoder / fly i`: u (row i's chip lifts off the text it names, flies sideways out of the panel at full opacity and vanishes as it lands). Rows are 32 px |
| `new Table({ id, x, y, title, cols, rows:[{label, steps:[[...],...]}] })` | `<id>`: in, step (s.set), flash (pulse per step), col, x, y |
| `new Ladder({ x, y, w, title, rungs:[{name, time, space, cost}], pick })` | `Ladder`: in, shown, hl, pick, x, y. The pick stamp hangs below the last rung |
| `new CodePanel({ code, x, y, fontSize = 30, lineHeight = 1.3 })` | `Code`: in, reveal (lines), line (active line, glides; `code.find('text')`), x, y, dim, tilt. Keep `fontSize` 30 to 36; the active line gets a highlight bar, the others stay readable |
| `new QuestionCard({ T, x, y, w })` | `Question`: in, q (line id), a (line id), n, timer (0..1 of think), flip |
| `new TitleCard({ title, subtitle, badge })` | `Title`: in, out |
| `new ChapterCard({ T })`, `new ChapterTag({ T })` | `Chapter`: n, u (0 → 0.5 covers → 1); it sits in `stage.over`, above the HUD. `ChapterTag`: n, in |
| `new Bursts({ slots: 2 })` | `Burst i`: in ('back' ease), text (words in Bangers, digits in Inter Black), color (gold/good/bad/accent/cool), x, y (kept inside the safe area), rot, size |
| `new Caption({ T })` | `Caption`: in. Shows the current line's `cap` itself (markup: `O(...)`, numbers, `^`) |

Layers by depth (px behind the subject; the camera moves each by its depth): `far` 1800 (skyline, glow orbs),
`floor` 520 (perspective grid), `subject` 0 (graph, decoder, tables, panels by default), `panels` −140,
`fore` −620 (bokeh), then the screen-space `hud` (captions, bursts, tag) and `over` (the chapter card). The
`Content` object (in, 0..1) fades the subject and panels layers and the `hud` together; `over` never fades. Pass
`layer: 'panels'` to put a panel nearer the camera. Text and numbers in panels come from data or `cap`, not
from Theatre strings, except the few documented string props (route, tag, badge, q, a, text).

**Text sizes** live in `tokens.js`: `SIZE` for panels and cards, `GRAPH_TEXT` for the graph (weights, badges,
tags, node numbers, running sums), each with a `min` in screen px. The graph grows a label inside its plate when the
graph scale and the camera dolly would put it under its minimum, so a shrunken graph still reads at 32 px.
Dimmed text keeps at least 4.5:1: a dimmed edge fades its stroke and mixes its weight toward `inkDim`; a dimmed
code line or decoder row stays readable, and focus comes from the highlight bar and colour. Graph tags, badges
and weights never fade in slowly: they reach full opacity early in their entrance and finish with a scale pop.
Time a panel's entrance so it has landed before the line's still (65% into the line) is taken.
`python3 $S/legibility.py --project .` measures every text in the stills (the visuals gate needs 0 failing).

Adding a component: a class with `id`, `objects()`, `mount(stage)` (build DOM under `stage.layer(name)`),
`apply(V)` using the cached `setStyle/setAttr/setText` from util.js, and `rect()` if the camera should frame
it. Add it to `components` in world.js. Keep imports DOM-free at module level (build.mjs imports the kit in node).

## 7. Recipes

`R = recipes(s, T, W)` (src/theatre/recipes.js). They only add keyframes, so they stay keyed to line ids.

- **Camera framing:** `R.focus(rect, t, dur, { zoom, orbit, tilt, roll, pad, margin, tag, extra: { dof } })`
  solves pan and dolly so `rect` fills the safe area above the caption band. It projects the rect the way the
  stage draws it (each part's layer depth, a panel's own tilt, the orbit's perspective) and shrinks until it fits,
  so `zoom` is capped by the frame. Each part of an `R.union` that would run under the chapter tag (`TAG_ZONE` in
  tokens.js) makes the whole frame drop below it (`tag: false` turns this off). Rects: `G.rect([0, 1, 3])`,
  `W.code.rect()`, `R.union(a, b)`; an extra rect in the union reserves empty room (headroom for a burst). Move
  the graph with `s.to('Graph', { x, y, s }, ...)` to make room for panels; it never leaves.
- **Chapter beat:** `R.chapter(n)` uses the silence between chapters, and the card never sits over content:
  after the last word of chapter n-1, everything on screen (subject, panels, caption, tag, bursts: `Content.in`)
  fades fully out over 0.28 s; only then does the diagonal band swipe in over the bare sky and city, hold and swipe
  out; once it has gone, the content fades back in from the first line's slot start (when its caption appears) and
  is fully back by the first word, with the corner tag showing the new chapter. With the default 0.8 s chapter gap
  the card is up about 0.85 s. If the silence is shorter, the card borrows from the first line's lead silence, never
  from a spoken word. Pair it with `R.mood('night'|'ember'|'neon'|'dawn'|'dusk', t)` for a colour arc across the
  film. It returns `{ t0, end, back, shown }`: move the camera and the graph between `t0` and `back` (nobody sees
  it; `shots.js` uses `hidden(c)` for the duration), take the old chapter's panels off by `t0` and bring the new
  ones in at `end` or later. A chapter's first line has a 1 s lead (its voice starts 1 s after its slot start), so
  anything the subject needs to be on screen (a graph appearing for the first time, as in chapter 1) enters at
  `back`, as the card leaves, never at `T.at(first line)`: qa.py's `chapter-entry` check wants it there as the
  voice starts.
- **Decode an input:** `s.to('Decoder', { in: 1, rows: 11 }, ...)`, then per row
  `s.to(\`Decoder / fly ${i}\`, { u: 1 }, T.word(id, '...'), 0.9, 'inOut')` with the edge's `draw` and `label`
  tweened as the chip lands.
- **Trace a route:** `R.fly(i, '0-1-3', t, dur, { result: 'good'|'bad'|'hot', rings, land, heat, sum })`
  returns the end time; `R.land(i, t)` removes the token. Ghost tokens: `{ heat: false, land: false }`.
- **Reject an illegal route:** `R.reject('0-1-2-3', t)` (rose edges, strike, shake) plus
  `R.burst(0, 'TOO MANY STOPS!', t, { color: 'bad' })`.
- **Think countdown:** `R.question('q1', 1)` (card in, ring runs over the think pause), `R.answer('a1')`
  (flip). The next question: `R.question('q2', 2, { flipFrom: true })`.
- **DP row update:** `s.set('Table', { step: k }, t)` and `s.pulse('Table', 'flash', t)`; cells that changed
  flash. Show old/new rows side by side for "copy first" ideas.
- **Code walkthrough:** `s.to('Code', { reveal: n }, ...)`, then `s.to('Code', { line: code.find('next[v] =') },
  T.word(id, '...') - 0.1, 0.5)`; the bar glides. Edits to the code never break line numbers.
- **Punctuation:** `R.burst(i, '700!', T.word(id, 'seven hundred'), { x, y, color, shake })`, one per
  chapter at most. It starts 0.18 s early (`lead`) so it is full size on the payoff word. Put it where it covers
  no text (an empty corner, or headroom framed in with `R.union`); skip it when no such place exists.

## 8. Rendering

```bash
cd source && npm run build && cd ..
node $S/capture.mjs --page source/index.html --bench 3            # one worker's fps + ETA
mkdir -p build && node $S/capture.mjs --page source/index.html --out build/silent.mp4 \
    --workers 2 --max-minutes 100 > build/render.log 2>&1          # background it; poll tail -3 build/render.log
```

Exit 3 means the budget ran out: run the same command again; finished 20 s segments are kept. Rebuilding
with no changes does not restart segments; changing anything in `source/` does (by design). Stills:
`node $S/theatre_look.mjs` (build + chapter and line stills + contact sheets into `stills/`), or
`node $S/capture.mjs --page source/index.html --stills 12.5,31 --stills-dir stills`.

Measured here (4 CPUs shared with 8 other jobs, headless Chromium screenshots, 1080p30): 2 to 4 frames/s per
worker in the bench; the demo's earlier 62 s cut rendered in 9 to 11 minutes with 2 workers (2.8 to 3.4 frames/s), so a
6-minute film takes about 35 to 65 minutes with 2 workers: one 2-hour job. The output is about 11 Mbit/s.
The cost is compositing and encoding, not JavaScript (`renderFrame` takes 3 to 7 ms). What makes it slower:
each full-frame layer, live CSS `filter: blur()` on a moving element (3x), large `box-shadow`s, and anything
full-frame that changes every frame (moving grain: 6x the bitrate, and a slower encode). The stage avoids
them: background layers are band-sized canvases, depth of field cross-fades a pre-blurred copy, bokeh are
small DOM discs, and the grain holds still.

## 9. Studio: hand-tweaking keyframes (optional, laptop)

```bash
cd source && npm i --save-exact @theatre/studio@0.7.2 && npm run studio
# open http://localhost:8080/source/studio.html (the server serves the project folder, so narration plays)
```

Studio shows every object in the outline (Camera, Sky, Graph / node 0, ...), the generated keyframes on the
timeline, and the narration (click once to enable audio). Drag keyframes, change values, then select the
project "Explainer" in the outline and press "Export Explainer to JSON". Studio keeps edits in browser storage;
after a rebuild it says "Browser state is not based on disk state": choose "Use disk state". The generated
keyframes stay the source of truth, so port tweaks back:

```bash
node tools/studio-diff.mjs ~/Downloads/Explainer.theatre-project-state.json
# ~ Film :: Camera.z @ 3.629s: time 3.629 -> 3.829s; value 30 -> 80  p1 +0.00s
# + Film :: Graph / node 1.glow @ 8.100s = 1  [bezier]  p2 +1.28s
```

Each line names the object.prop, the time and the nearest narration line, which is what `s.to(...)` in
shots.js needs; the base is what shots.js generates now. To preview an export in a browser:
`index.html?state=export.json`. To render it as-is, save it as `source/theatre-state.pinned.json`: the build
then ships it instead of the generated keyframes and prints `PINNED` on every build. A pinned state does not
follow a re-voice; delete the file to go back.

## 10. The 3D variant (Three.js)

`src/variants/three.js` binds the same sheet, objects and keyframes to Three.js: nodes become pucks on a
floor, edges arcing tubes (`draw` → `setDrawRange`), tokens cones that fly the same routes, the Theatre
`Camera` an orbiting perspective camera, `Sky` the background and fog. The 2D kit (captions, chapter cards,
bursts, decoder, tables, code, question) stays on top as a screen-space overlay, and the decoder's chips fly
to the projected 3D positions. Same `world.js`, same `shots.js`, same timing: re-voicing re-times both.

```bash
cd source && npm i --save-exact three@0.186.1 && node tools/build.mjs --3d && cd ..
node $S/capture.mjs --page source/index-3d.html --webgl --stills 20,45 --stills-dir stills
```

SwiftShader (no GPU) renders it at about 1 frame/s per worker here (the 2.5D page: about 4 in the same bench). It is a working example of the
binding, not a finished 3D look: for lights, shadows, bloom, models and the 3D kit use the `threejs-video`
skill and keep Theatre as the animation system by binding its objects the way this file does
(`rig.values(t)` → set mesh transforms/materials → `renderer.render`).

## 11. Gotchas

| Symptom | Cause | Fix |
|---|---|---|
| `!=` or `<=` drawn as one glyph in code | ligatures | the kit uses JetBrains Mono **NL** files and `font-feature-settings: "calt" 0, "liga" 0` on `.mono`; keep both |
| A "700!" burst reads "100!" | Bangers' 7 looks like a 1 | the kit sets burst digits in Inter Black and switches chapter numerals to Inter when a chapter number has a 7 (`.num-safe`); put numbers that matter in Inter or JetBrains Mono |
| `→`, `∞` or `≤` in a fallback font | fontsource Inter/JetBrains subsets lack them | the kit loads `inter-ui` InterVariable (full glyph set); keep it |
| Fonts differ between stills and render, or a flash of fallback | fonts not loaded before frame 0 | main.js awaits FontFace loads and `document.fonts.ready` before READY; fonts are bundled as data URLs (no network) |
| Every prop sits at its default; no animation | state not passed, or keys differ | `getProject(id, { state })` with the generated state; object keys are normalised (`"a/b"` → `"a / b"`), `keys.js` emits the normalised form |
| `process is not defined` in the page | Theatre reads `process.env.NODE_ENV` | build.mjs defines it (`production`; `development` for Studio) |
| A prop shows its first tween's value from t = 0 | Theatre holds the first keyframe's value before it | the compiler adds a keyframe at 0 with the default; keep using `s.*` rather than hand-editing state |
| NaN or a jump at one instant | two keyframes at the same time on one track | the compiler offsets them by 1 ms; do the same in hand-made state |
| Text props (route, tag, q) interpolate oddly | strings cannot tween | `s.to` turns them into holds; type is `hold` in the state |
| An rgba prop is an object of four numbers | Theatre infers a compound from `{r,g,b,a}` | `rig.js` declares them with `types.rgba` |
| Values lag one frame or stay stale when seeking | `onValuesChange` is RAF-driven | read `obj.value` right after setting `sequence.position` (rig.values does) |
| The film stops early | `sequence.position` is clamped to the sequence length | `length` = `TIMING.total`, set by the compiler |
| Render 3x slower after a style change | live `filter: blur()`/`backdrop-filter` or huge shadows on moving layers | blur static art once into a canvas; keep shadows small |
| Words in captions run together | flex containers collapse spaces between inline spans | wrap rich text in one `<span>` (Caption does) |
| A panel is cut off after a camera move | camera numbers typed by hand | frame with `R.focus(rect)`; the rects come from the components |
| `silent.mp4` near 70 Mbit/s, slow encode | full-frame noise that changes every frame | keep the stage's `grain: 'still'` (default); `'moving'` is filmic but about 6x the bitrate (66 vs 11 Mbit/s measured) |
| A resumed render starts over | something in `source/` changed | expected; a no-change rebuild is safe (writes only changed files) |
| `timing.js` changed but the film did not | stale bundle | timing.js is loaded at runtime and the page recompiles on a hash mismatch; still run `npm run build` |

## 12. Laptop differences

- Install Playwright where you run `capture.mjs`: `npm i -D playwright-core` and point `CHROMIUM` at Chrome, or
  `npx playwright install chromium`. Use `--workers` up to your core count; 1080p runs several times faster.
- `?play=1` previews in real time with the narration in any browser served over http
  (`python3 -m http.server` in the project folder, then `/source/index.html?play=1`).
- Studio (section 9) is laptop-only: it needs a browser window and a person dragging keyframes.
- The 3D variant: `GPU=1 node $S/capture.mjs --page source/index-3d.html --webgl ...` uses the real GPU.

## 13. Themes

The film keeps the kit's own palette (`original`) unless a theme file is emitted. The contract and the list of
30 themes are in `references/themes.md`.

- **Theme file:** `source/src/kit/theme.js`. The template ships a stub (`export const THEME = null`), which means
  `original`, pixel for pixel the verified starter look.
- **Emit:** `python3 $S/vstate.py set theme=<id>`, then
  `python3 $S/theme.py emit <id> --format js --out source/src/kit/theme.js`, then `npm run build` (the theme is
  bundled, so every rebuild after a re-emit picks it up). To go back to `original`, copy
  `$SKILL/assets/template/src/kit/theme.js` over it.
- **One place:** `tokens.js` imports the theme. `themed()` maps it onto the kit's roles in `C`, `themedMoods()`
  builds the sky moods, and `cssVars()` builds every CSS variable `style.css` reads. No other file holds a colour.

| Kit role (`C.*`) | Theme token |
|---|---|
| `ink`, `inkDim`, `muted` | `text`, `muted`, `dim` |
| `accent` `good` `bad` `gold` `cool` `violet` (fills: edges when hot, bars, stars, chips, glows) | same names |
| `*Ink` (captions' numbers and O(...), panel kicks, table labels, ladder O(...), stamps, landed decoder rows) | `<hue>Ink` |
| `onGold` (tags, sums, title badge, kicks, decoder chips), `onGood` (ANSWER kick), hot node label | `onGold`, `onGood`; the label picks the best of `onAccent`, `onGood`, `text` on its face |
| `viewport`, sky `top` | `bg`; sky `bottom` is `bg2` tinted 8-12% toward the chapter light |
| panels, plates, chapter band, stamp | `panel` (0.95 for panels); edges `line2` |
| `node` face / rim, idle `edge` | `panel` inside a `dim` rim, `dim` (shapes keep about 3:1 on the ground) |

| burst words | the star's `on<Hue>` (a dark word drops the outline) |
| sky moods dusk, dawn, ember, neon, night | `lights[0..4]` (warm, gold, bad, accent, violet) |

On a light theme (`tone: light`) the grain multiplies (screen on dark), soft shadows drop to 35%, node halos,
glows and the foreground bokeh are halved or less, the horizon glow becomes a 20% tint of the sky, the scrim and
the vignette are faint `deep` washes, and the city is a paper cut-out a step darker than the sky. Overlays sit
above the text, and the solved inks clear 4.5:1 with little margin, so keep any overlay you add faint. Check every
theme you ship with the review stills and `legibility.py`, as for the original palette.

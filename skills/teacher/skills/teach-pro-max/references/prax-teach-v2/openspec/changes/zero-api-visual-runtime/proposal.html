Why

The existing teach-pro-max engine has the teaching contract, learner state, visual routing, and static artifact path, but its planned offline visual runtime is still only a tracker. The learner needs a small, deterministic environment where they can predict, manipulate, compare, receive ordered hints, and export inspectable evidence without an API, telemetry, or hidden subscription backend.

This change turns the repository-defined Zero-API Visual Runtime plan into one OpenSpec-governed implementation, while keeping the host tutor and the universal static fallback intact. It also makes engineering completion and genuine human-learning evidence visibly separate.

What Changes

  • Add a separately versioned, offline visual-runtime package inside the candidate.
  • Add versioned visual-lesson and learning-receipt contracts with validation, import, export, inspection, and deletion.
  • Add reusable accessible components for state stepping, parameter manipulation, synchronized comparison, ordered hints, and receipt display.
  • Build three local lessons: Python floating-point representation, Rubik's legal moves, and concurrency lost updates.
  • Preserve a complete static, JavaScript-off, print, zoom/reflow, and reduced-motion path for every lesson.
  • Enforce a no-network/no-API/no-telemetry runtime boundary with deterministic builds and local asset containment.
  • Add one explicitly bounded, build-time-only Lean experiment with a static equivalent and a keep-or-revert decision.
  • Prepare evaluation, accessibility, privacy, security, deterministic-build, review, packaging, and rollback evidence.
  • Update the canonical tracker and its Markdown/HTML views from evidence; never convert synthetic or planned results into human-learning claims.

Capabilities

New Capabilities

  • offline-visual-runtime: deterministic local lesson runtime, shared components, fallback routes, and receipts.
  • visual-lesson-contracts: versioned lesson specifications, learning receipts, formal receipts, and validators.
  • visual-learning-labs: floating-point, Rubik's move, and lost-update lessons using the shared runtime.
  • build-time-formal-receipts: one pinned Lean adapter and proof-state export with a removable boundary.
  • runtime-evidence-and-packaging: no-network enforcement, evaluation capture, exact-byte evidence, review, and candidate packaging.
  • teaching-runtime: explicit receipt bridge to the offline visual runtime while preserving host-chat interpretation and static fallback behavior.

Modified Capabilities

None. The repository has no pre-existing OpenSpec capability specs; these are new contracts for the candidate.

Impact

  • Adds runtime, lesson, schema, fixture, test, build, and evidence files under the candidate repository.
  • Adds repo-local OpenSpec artifacts under openspec/ and a project-local Codex skill configuration generated by openspec init.
  • Extends the existing Python/Node toolchain with only pinned, project-scoped dependencies required by the runtime and one build-time Lean experiment.
  • Does not add an API client, telemetry, remote runtime asset, browser automation, or automatic learner-data upload.
  • Does not install or replace the global teach-pro-max skill until a separate promotion decision is made.

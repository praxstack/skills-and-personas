Codex CLI: supported readability settings

Applied and verified on Codex CLI 0.163.0, 19 October 2026.

Catppuccin Mocha gives code and diffs a consistent palette. A compact colored footer exposes the model and reasoning level, remaining context, available usage limits, and Git branch. Animations are disabled and formatted output is retained.

What this improves, and its limit

The installed theme picker confirms the current theme and displays a real syntax/diff preview below. The installed status-line picker confirms every selected identifier. Limits and branch disappear when unavailable; testing in /tmp therefore showed no branch.

Codex does not expose supported settings for arbitrary conversation boxes, message borders, a replacement header, or custom separators between every user, assistant, and tool message. These settings improve the supported syntax and footer surfaces; they do not redesign the conversation layout. The terminal title and terminal-wide theme were preserved.

Verification

A new disposable session ran with --no-daemon --strict-config -C /tmp, opened /theme and /statusline, then exited normally with /quit. Exit code: 0. No model request was sent. No existing session was restarted. Startup displayed two warnings before and after the UI edit; unrelated integration warnings were outside this task.

All content outside the [tui] table remained byte-identical to the private backups. Within the table, only the five intended keys changed. Existing other keys were preserved. The already-managed chezmoi create template has the same five settings.

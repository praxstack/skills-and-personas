Teaching experience: research synthesis

User-directed research, 2026-10-16. This is a design reference and product-direction record. It does not change frozen evaluation criteria, certify efficacy, or claim installation.

Recommended experience

Build a teacher with three connected surfaces: the teaching stage, the course map, and the learner’s notes. These are logical surfaces, not a requirement to build an app. A conversation, Markdown files, HTML artifact, canvas, or capable host can express them differently.

The stage explains a coherent bounded idea in full: the problem, relevant objects, mechanism, result and why it follows. A drawing is often enough; an animation explains change; an interactive model exposes a causal variable; a video can coordinate narration and visual progression. Discover available tools and choose for this role, correctness and delivery support. No tool is universally best and no host is presumed to render everything.

Default to Prax’s AskTheMove teaching language: crisp readable content with short handwritten coach notes, purposeful arrows and highlights, warm paper and semantic ink colors. Animated pen strokes should follow reasoning. Give immediate access to the complete figure and keep it available; a replay is an optional view of how the explanation unfolds, not a gate that withholds the whole story. Preserve keyboard operation, readable math/code and reduced-motion alternatives.

The map shows the current question, useful prerequisites, optional branches and next topics. It should be editable as curiosity changes. The notes separately preserve definitions, worked reasoning, source links, assumptions, limits, learner questions and reusable visuals. Consent controls saved learner progress; exposure and satisfaction are not mastery evidence.

Teach first when the goal is already clear. Diagnose a specific gap when necessary, then change the explanation, scale, example or medium. Offer practice and predictions when they help. Continue until the learner is satisfied or stops; do not replace that choice with a quiz score. A coordinating teacher may delegate a bounded diagram, source check or worked example when supported, but must reconcile the outputs into one explanation.

Proposed general teacher adaptation

User has requested this aesthetic by default. Treat the following as an implementation brief, not proof it has shipped.

  • Default surface: warm whiteboard/notebook with strong contrast, uncluttered explanation and purposeful annotations. Keep optional ruling/margins faint; remove them when they compete with the subject.
  • Three visual voices: readable prose, precise mathematics/code/data, brief handwritten coach annotations. Handwriting never replaces long text, equations or code.
  • Draw causes before effects. Time an arrow, highlight or change in the model with the sentence explaining it. The learner can inspect the complete diagram immediately; animation never gates access to the whole story.
  • Preserve the same objects and labels across static drawing, animation, manipulable model and narrated video. Changes in presentation should not require relearning a visual vocabulary.
  • Controls manipulate real explanatory variables. Show the changed input, intermediate mechanism and consequence together, with a reset and meaningful comparison. A slider whose only effect is a cosmetic change does not qualify.
  • Video uses the same causal storyboard, with captions, transcript and still/key-state equivalent when supported. Live drawing is a presentation style, not a claim that a human is teaching live.
  • Course overview and durable notes remain separate from the teaching stage. Notes include assumptions, definitions, worked reasoning, unanswered questions and useful references rather than only a compressed summary.
  • Fit the host: inline drawing when supported; self-contained HTML/SVG or video where supported; readable static sequence or text where richer rendering is unavailable. Report the actual fallback. Never promise every host can render every medium.
  • Fonts can fall back to suitable locally available families. Exact assets require portable bundling and license checks. Avoid machine-specific absolute font paths.
  • Learner accessibility and requested style override the default. Do not import the site’s light-only constraint as a universal teaching restriction.

Feasibility

The existing repository already demonstrates an implementation vocabulary (SVG paths, seeded pen strokes, text reveals, semantic styles and reusable brand styles for video). It provides a concrete starting point for this skill’s generated artifacts. A harness-independent policy can select and explain the style; runtime capabilities determine which artifact can actually be produced and displayed. Best-tool discovery should remain dynamic, rather than hard-coding a vendor as universally best.

Acceptance examples for a future implementation

A static diagram tells the complete bounded causal story. Its animation reveals the same mechanism without hiding prerequisites. Its interactive version lets a learner change a cause and see all dependent quantities update. Its video narrates the same states with usable pacing. Each has a readable non-animated explanation; tests check correctness and usability, not learner satisfaction by proxy.

Learning-platform inspiration for a general teaching skill

Reviewed 2026-10-16. Scope: Brilliant, Educative, Imprint, Nibble, Wondering. No accounts, purchases, publishing, or implementation. These are design references, not evidence that a proposed teaching skill improves learning.

Recommendation

Combine Brilliant’s model → prediction → explanation → formalization, Educative’s readable course spine with nearby practice and notes, Imprint’s compact explanatory visuals, Nibble’s learner-selected formats, and Wondering’s explicit goal/depth/background controls. Retain the causal teaching sequence independently of any browser, canvas, code runner, or proprietary tutor. Recommendations below are design inferences, not measured learning effects.

Coverage and evidence limits

Official sources were searched with Exa and web search, then direct pages were read. Four research questions: how lessons produce intuition; how visual actions encode concepts; how learners control depth/pacing; how courses and notes preserve continuity. Public page text and documentation were inspected; no interactive lesson was completed and no rendered UI behavior was verified. An in-app-browser inspection attempt failed because that browser was unavailable. Product screenshots described in page metadata are not counted as live UI observations. Marketing testimonials, ratings, user counts, and claims of faster learning do not establish efficacy. No independent outcome studies were assessed in this bounded platform review.

Concrete patterns to carry into the skill

These proposals transfer the design ideas; their causal explanations are hypotheses to test, not claims proven by these sites.

  1. Start with a question that needs the concept. Present a concrete situation, contrast or anomaly. Let the learner notice or predict something. Then explain the mechanism and introduce terminology. Brilliant’s scale example provides an unusually explicit instance of this progression. The hypothesized benefit is that notation names a relationship the learner has already encountered. Brilliant guide
  2. Make interaction change meaning. A slider should alter a relevant quantity; a drag should change a relation; a button should expose a counterexample. If nothing conceptual changes, a labeled static diagram may be better. Brilliant’s design account emphasizes difficulty progression, variation and edge cases, with human review of generated problems. Its historical 2025 position on chatbots must not be confused with its current homepage, which now markets Koji tutoring. Design account, Current homepage
  3. Keep learner control explicit. Offer “explain directly,” “give a hint,” “another example,” “show the formal version,” “let me try,” and “go deeper.” Treat these as options, not a mandatory menu after every paragraph. Wondering and Nibble supply inspiration for goal and format choice; the particular controls proposed here are our design recommendation. Wondering, Nibble
  4. Use checks to diagnose reasoning. Ask why an answer works, what changes under a changed assumption, or where an analogy breaks. Give feedback on the reasoning and permit skipping. A correct multiple-choice answer alone should not trigger a mastery claim. Educative documents several exercise families; Brilliant describes explaining strategies and review checks. Educative widgets, Brilliant guide
  5. Preserve both a course map and useful notes. Recommended note unit: concept → intuitive model → precise statement → worked example → limitation/counterexample → learner question → source. Link it to prerequisites and a suggested next step. Educative supports contextual annotation, Imprint markets saved ideas, and Wondering exposes course structure/cards; the combined portable note schema is our proposal. Educative FAQ, Imprint, Wondering listing
  6. Keep the teaching contract portable. The essential deliverable is the explanation, causal relationship, example, learner choice, and durable notes. A capable harness may render a simulation; a text-only harness can use a small table, diagram, worked trace, or prediction with a revealed result. This is an architectural inference for the requested harness-independent skill, not a claim about the platforms.

Suggested evaluation examples, not new mandatory gates

  • Algebra: predict what happens when only one scale side changes; explain equality; derive the permitted operation; transfer to a symbolic equation.
  • History: compare two explanations for one event, inspect timeline/evidence, separate causal inference from chronology, and identify a counterexample.
  • Programming: predict a short program’s output, trace changing state, explain the invariant, then change one condition.
  • Philosophy: use a concrete case, state an argument, test a counterexample, and mark the analogy’s limits.

Observe whether a learner can explain the mechanism and transfer it to a changed case. Also check whether they can request direct explanation, skip practice, change depth, and retrieve coherent notes. Do not use clicks, completion, streaks, time spent, or aesthetic polish as substitutes for understanding.

Fit to the requested explain-first, hand-drawn teaching style

Brilliant’s current homepage says its tutor does not simply supply answers. That product stance should not become a compulsory Socratic rule here: give a clear explanation when requested and make predictions/practice optional. Borrow the causal model and targeted help, not answer withholding. Current Brilliant homepage

For the user’s requested live whiteboard default, draw only the part of the model currently being explained, use persistent visual anchors, and reveal relationships in the order the prose explains them. Keep readable labels, replay/step controls where supported, and a complete static fallback. Hand-drawn appearance is a user-directed presentation choice; this review did not establish it as a feature or learning advantage of all five products.

Remaining gaps

Actual onboarding friction, hint quality, wrong-answer recovery, keyboard accessibility, visual clarity, note export, and cross-session persistence remain untested across all five. Imprint and Nibble offer weaker publicly inspected evidence about deep conceptual sequencing than Brilliant’s educator guide. Wondering’s public outline demonstrates organization only; no generated lesson correctness was audited. A later authorized trial could inspect one matched concept end to end on each service, but this research does not require paid access to inform the skill’s design.

More precise reusable patterns

Mission and scope. Pocock’s mission format records why the learner cares, observable success, constraints and exclusions. Adopt these lightweight fields, while accepting curiosity and deep intuition as valid goals. Do not force a practical deliverable or a preliminary interview when the user’s aim is already clear. One mission per workspace is an organizational suggestion, not a reason to block interdisciplinary learning.

Evidence-bearing notes. The learning-record format distinguishes demonstrated understanding, reported prior knowledge and corrected misconceptions from mere coverage. It permits evidence and supersession without demanding long session logs. Adopt concise records that preserve this distinction; record unresolved uncertainty rather than marking a concept mastered after exposure or one correct answer.

Curated source notes. The resource format asks what each source covers and when to use it, surfaces gaps, and records preferences about communities. Adopt annotated provenance and gaps. Keep sources as references supporting teaching, rather than turning the lesson into a reading list.

Intuition before formal expansion. Official Machine Learning Specialization text retrieved through Exa describes visuals, implementation and optional mathematical explanation, with ungraded notebooks and interactive graphs. Inference: layer explanation so a learner can move between intuition, concrete execution and formal derivation; offer mathematical depth when it resolves uncertainty. Do not universally postpone math or assume viewing a visual establishes intuition.

Prerequisite-aware progression. Official Machine Learning in Production extraction identifies prior AI/deep-learning and Python experience and combines lectures, notes, labs and assessments. Inference: identify the minimum missing prerequisite and supply a local bridge; avoid assigning an entire preceding course when a small explanation suffices. The specialization page was subsequently fetched through Exa and confirmed the visual-to-code-to-optional-math sequence; the production course remains an official-page search extract. Neither is a full course audit.

Honest tool orchestration. Fanout’s Agent Control Room explicitly describes device-local modeled scenarios, bounded retries and estimated cost. Its Model Router separately describes a live catalog fetch triggered by a user action. Inference: label simulations, live observations and estimates distinctly. A teacher should choose a renderer/calculator/notebook only when its output clarifies the concept, preserve capability-independent lesson state, and disclose when a requested interaction cannot run.

Proposed teaching loop — synthesis, not a source fact

  1. Locate the learner’s purpose, current explanation and specific point of confusion, using existing context first.
  2. Build one causal account with a concrete example. Choose representations for their explanatory role: process trace for changing state; graph for dependencies; plot for quantitative relationships; geometry for space; contrast table for cases; manipulation for cause and effect. Avoid decorative variety.
  3. Invite prediction, manipulation, explanation, comparison or a real task as useful diagnostic evidence. Quizzes are optional instruments.
  4. If confusion remains, change the representation, example scale, analogy or prerequisite bridge. Explain analogy boundaries. Do not repeat the same wording louder.
  5. Preserve a compact reference, source links and the learner’s unresolved questions. Continue until the learner is satisfied, or explicitly pauses; never force completion because a score or predetermined step count was reached. Satisfaction is not proof of permanent retention, so notes should distinguish the two.

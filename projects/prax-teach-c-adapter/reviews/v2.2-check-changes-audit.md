# v2.2 check-changes audit: every test, gate, checker, rubric and verifier change from v2.1-rc1 to v2.2-rc1

Independent, read-only review, 2026-10-19. FREEZE-v2 item 8: a changed test or gate counts only after an independent review classifies it as a bug fix or a stricter check. This file is that review.

## Short answer

No gate was weakened to show progress. Two small changes are weaker than what they replaced, and neither is what made a Track A or Track B result pass:

1. **`lexicon/c.json`: "rayalue" added to ReLU's accepted heard forms (B5, `bbd7720`).** The worker whose narration the check measures widened the check's accept list in the same round.
2. **`tests/test_still.py:148`: the first-note position bound became two-sided** (`0 <= gap <= 48` became `abs(ny - top) <= 48`). Current builds measure +1.2 px, so the one-sided bound would still pass.

One change needs Prax's eye but is not weaker: the IVE explore check now samples after the last answer (`visual.py:567`), which matches the gate's own rc1 comment, so EXPLORE before the answer is never checked for a live control.

## WEAKER findings, in full

### W1. ReLU heard form "rayalue" added (lexicon v5, `bbd7720`, B5)

- **Before:** ReLU `heard` = relu, ray lou, ray loo, rayloo, ray-loo, re lu, relo, raylu, ray lu, rayleigh, really. The sync gate and AC-10.5's lexicon check fail a cue whose ReLU is heard as none of these.
- **After:** "rayalue" is accepted too. The spoken form also changed from "ray-loo" to "raylu".
- **Why weaker:** it widens an accept list. The B5 worker made the change in the round its narration was measured. FREEZE-v2 says "A run changes the candidate or the evaluator, never both." The commit gives a reason ("the same film segments are heard as relu/raylu in isolation"), but no independent check backs it, and no test pins the isolation result.
- **Size:** one token, one lesson (neuron). The list already held loose forms ("rayleigh", "really") from rc1.
- **Fix:** have someone other than the B5 worker re-run whisper on the isolated neuron segments and record the result. Keep "rayalue" only if they confirm it. Otherwise remove it and let the line fail.
- **Evidence:** `package/prax-teach/lexicon/c.json` (ReLU entry). Commit `bbd7720` message. I could not re-run the isolation test because the neuron build in the main tree is still `draft` and I was told not to build.

### W2. First-note position tolerance became two-sided (`tests/test_still.py:148`, `0731a91`, B1)

- **Before (rc1):** `0 <= ny - code_card_top <= 48`. The first note could start up to 48 px below the code card top, never above it. A second assertion required the output to sit beside the code card.
- **After:** `abs(ny - mechanism_text_top) <= 48`. The note may now start up to 48 px above the figure top. The output-beside-code assertion is gone.
- **Why weaker:** the old bound rejected a note above the reference and the new one accepts it. Removing the output assertion is fine, because AC-10.1 removes the code card, so it has nothing left to measure. A new assertion was also added, that no note badge sits inside a mechanism, and that one is stricter.
- **Size:** small and not used. Switch wide still, both themes: `ny - top = +1.2 px` (measured in the audit worktree), so `0 <= gap <= 48` would still pass.
- **Fix:** put back the one-sided bound, `0 <= ny - top <= 48`.

## Flagged items (the ten areas asked about)

### 1. `verify/media.py` clamps whisper word ends to the audio length (B5, `de89804`). **Bug fix.**
- Before: a whisper word could end after the audio. Measured case: 112.2 s in a 108.67 s film. No trailing silence could hold it, so `refine` put the speech end 5 s after an in-sync cue.
- After: `clamp_to_audio` (`media.py:136`, called at `:131`) caps `end` at the probed audio duration. Starts are untouched.
- Not weaker: speech can't end after the audio. The clamped end then snaps to the real silence start (107.022 vs cue end 107.07). The 0.5 s sync tolerance is unchanged.
- Run: `test_media.py::test_whisper_word_never_ends_after_the_audio` passed. It also asserts that the unclamped input gives 112.2, so it fails on the old code.

### 2. `test_ive.mjs` observation window 8 s → 13 s (B5, `ed23c56`). **Bug fix.**
- Before: `explanation_first_default` polled at most 160 × 50 ms. After: 260 × 50 ms (`test_ive.mjs:172`).
- It is a bounded poll that exits as soon as `currentTime >= answer_at + 0.3`. The assertions did not change: the toggle is visible and off, the mode never reaches `ask`, the film never pauses, `t_end >= answer_at`, no samples fall in the gap, and the sealed text stays out of the chapters. A longer window gives more chances to catch a pause, not fewer.
- Why it was needed: at Kokoro 0.75 the switch answer cue comes 7.05 s after `pause_at`, and the poll starts 2 s before that.
- Related (not a change): the gate's own `_explain_job` polls 200 × 50 ms from `pause_at - 3` (`ive_predict.py:138`). For switch that is tight (about 10.35 s needed). It passed in the current build (`t_end` 20.51 vs `answer_at` 20.333), and it fails rather than passes if it ever runs short.

### 3. `claims.py` typed double slots `g_`/`d_` (B3+B4, `753e209`). **Changed requirement (AC-10.4), not weaker.**
- Before: an unknown slot matched `[^.!?]{1,60}?`, which can't match a decimal.
- After: `g_*`/`d_*` slots match only a number (`DOUBLE_SLOT`, `claims.py:60`, used at `:549`).
- Not weaker: rc1's `chrome.json` had no `{g_`/`{d_` slot, so no existing text gets accepted that failed before. The slots exist only in the two new live neuron templates (`k_live`, `k_tiny`). On any input the old slot could match, the new slot is narrower. A filled template instance is a teaching item (`chrome-claim`) and goes to the reviewers. Its numbers are checked against live state by AC-10.4 (`test_live_captions.py`, binary64 model). I also checked whether an untagged sentence matching `k_live` could get classed as plain chrome. It can't skip review, because projector items are teaching texts as a whole (`claims.py:686-698`).

### 4. `ive.explore-return` requires a live control (B3+B4) and `ive.predict-gated` rewritten for explanation first (A4b). **Stricter**, and **changed requirement (AC-6.8)**.
- `visual.explore_mode` (`visual.py:507`): before, `figure.panel` meant step mode, and a step back marked "step" passed (`step_back_marked`). After, it is `knob` or `missing`. Only an edit marked `yours` passes (`:543`), `live_model_builds` is always checked, and a panel lesson without `figure.explore` fails. Matches SPEC v1.4 AC-6.6 and D23.5. Current builds: switch `live`, one-byte and factorial `knob`, all checks true.
- Sample point (`visual.py:567`): the FILM / EXPLORE / RETURN flow now starts after the last answer cue. In rc1 the gate's comment already said "from a moment after every question is answered", but the code picked the first two-output state. For one-byte, factorial and neuron that was before the answer (21.5 s vs answer 47.8 s, 20.5 vs 51.3, 24.7 vs 55.2). The IVE has locked live controls before the last answer since rc1 (`ive.js locked()`, `unlock_cue`), for AC-6.3. **Classed as a bug fix.** Residual for Prax: AC-6.6 says every IVE offers a live control in EXPLORE, and before the answer it doesn't, by design. No test covers that window.
- `ive_predict.py`: the rc1 rule "the line before the pause invites a pick" (`INVITE`) is now inverted: `BARRIER` fails narration that asks to predict, pick, choose, commit or guess (`:46`, `:86`). This follows AC-6.8. Added: `MAX_ANSWER_GAP = 1.0` (no think gap in the MP4, `:45`) and a practice-off browser job (`default_problems`, `:260`). The practice-on half keeps every rc1 check and adds "the toggle turned practice on". `MAX_SILENCE`, `MAX_WPM` and `PAUSE_TOL` are unchanged.

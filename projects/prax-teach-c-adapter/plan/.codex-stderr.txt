## Section 1: Architecture

```
                         +------------------------- ptk (Python CLI) --------------------------+
  request ──▶ route ──▶ | mode+medium+workspace contract ──▶ lesson.json (model)               |
  (agent)               |                                    │  facts  claims  trace  storyboard |
                        |   capture/c_runner ── clang,gcc-16 ┘                                   |
                        |                                    ▼                                   |
                        |  projectors: still │ explorer │ qa │ cards │ video │ ivideo          |
                        |        │               │                    │         │               |
                        |        ▼               ▼                    ▼         ▼               |
                        |   SVG/PNG         HTML (self-contained)   HyperFrames  player page    |
                        |                                           +Kokoro TTS  +state bridge  |
                        |  gates: values · tamper · claims · contrast · screenshots · media     |
                        |                     ▼                                                  |
                        |            build-report.json (passed | failed | not-run)             |
                        +-----------------------------------------------------------------------+
  ported from v2: render_markdown (Node) · praxteach state+FSRS (optional) · tool registry (fixed)
  external: clang · gcc-16 · node · playwright · hyperframes · kokoro venv · ffmpeg/ffprobe · manim (route only)
```

**Data flow and shadow paths (capture → model):**
- **Happy path:** compile with both compilers, run twice, the outputs match, and they're stored as facts with sha256 hashes.
- **Missing input** (no source or program for a fact): `ModelError("fact X has no source")`. The build stops.
- **Empty stdout:** stored as an empty-string fact. Allowed, but a value gate that expects text fails loudly.
- **Upstream error:**
  - a compile error gives `CompileError` with the compiler's stderr;
  - a timeout gives `RunTimeout`;
  - outputs that differ between compilers give `CompilerDisagreement`, which is valid when the behaviour is implementation-defined, but then a claim must say so;
  - outputs that differ between runs give `NondeterministicOutput`.

**State machine (lesson build):**

```
  draft ──capture──▶ captured ──project──▶ projected ──verify──▶ verified ──package──▶ packaged
    ▲                   │ fail                │ fail                │ any gate failed
    └──── edit ◀────────┴─────────────────────┴─────────────────────┘ (stays failed; never "verified")
  Invalid: projected→packaged without verify (ptk refuses); verified with a not-run gate marked passed (schema forbids).
```

**Coupling.**
- Projectors depend only on `lesson.json` and the style tokens.
- Gates depend on `lesson.json` and the artifacts, never on how a projector works internally.
- The C repo isn't a dependency; the capture runner is self-contained.

**Scaling.** A build costs one TTS pass per scene (cached) and one HyperFrames render, about 2–4 minutes for 60–90 s of video. Ten lessons in a pack cost about 30 minutes. The first thing to break at 10x is TTS and render time, so a content-hash cache and `--only` flags per projector handle it.

**Single points of failure.**
- The HyperFrames CLI, which auto-upgrades: the version is recorded in the report, and a `ptk host check` warns on drift.
- The Kokoro venv: falls back to macOS `say`, disclosed in the report.
- Playwright: if it's missing, the visual gate reports `not-run`.

**Security architecture.** No network endpoints. The capture runner executes C that the agent wrote, so it gets a temp dir, rlimits, a timeout, process-group kill and no network (`sandbox-exec` profile where available, with the absence disclosed). Explorer and IVE HTML are self-contained, with a CSP meta tag that blocks all remote fetches.

**Production failures per integration.**

| Integration | Failure | Handled by |
|---|---|---|
| HyperFrames | Upgrades mid-build and changes lint rules | Version pin warning |
| Kokoro | Long-path bug in its pronunciation data (seen today) | Venv setup applies the proven fix |
| Playwright | Browser cache purged by an outside cleaner (seen on 2026-10-08) | `PLAYWRIGHT_BROWSERS_PATH` set to the package's own state dir |

**Rollback.** v2.1 installs alongside v2 under a candidate name. Acceptance flips the `prax-teach-v2` symlink, and rollback flips it back: one command, about 1 second.

**Beautiful version.** One file, the lesson model, is the only thing an author writes. Everything else is a pure function of it, plus captured runs. A new engineer reads `lesson.schema.json` and the six projector files and understands the whole system.

**Platform potential.** Topic packs (Phase 2), a cpx integration that cards and drills feed into, and other learners' workspaces.

Section 1 decisions:
- **D6.1** Per-scene HyperFrames sub-compositions. *Accepted*, completeness 10 versus 7 for one file, because it fixes the proof's lint warnings.
- **D6.2** The capture runner is self-contained rather than importing cpx. *Accepted*: separate products and no cross-repo coupling.

## Section 2: Error and rescue map

```

```

No catch-all handlers: every error class is distinct, and `ptk` exits 1 for a gate failure, 2 for host or environment problems and 3 for model errors.

**D7.1.** `GateNotRun` never counts as passed, and a build with any not-run gate is reported `incomplete`, not `verified`. *Accepted*, completeness 10. This is the direct fix for the v2 habit of passing on presence.

## Section 3: Security and threat model

| Threat | Likelihood | Impact | Mitigation in plan |
|---|---|---|---|
| Captured C program does something harmful (agent-written code; future: learner code) | Low | High | temp dir, rlimits (CPU, memory, file size), timeout, process-group kill, no network via sandbox-exec where available; D4.12 deferred |
| HTML artifact fetches remote content or runs injected text | Med | Med | self-contained output, CSP `default-src 'self' data:`, all model text HTML-escaped, a test injects `<script>` into a claim |
| HyperFrames telemetry and skill auto-update change `~/.agents` | High (seen today) | Med | ptk always sets `HYPERFRAMES_SKIP_SKILLS=1` and telemetry off; a test asserts the env |
| Prompt injection from web sources quoted in lessons | Med | Med | sources are data; the claims reviewer gets them as quoted data with a fixed rubric |
| Model download (Kokoro) supply chain | Low | Med | pinned kokoro-onnx version and file sha256 recorded; one-time, disclosed |
| npm advisories (2 high in v2's tree) | Med | Low | `npm audit` runs in CI-equivalent check; upgrade or document each |
| `/Users/prax` paths leaked in package | High (156 files in v2) | Low | packaging test greps for home paths |

**D8.1.** The sandbox for captured code is required. *Accepted*, completeness 10.

## Section 4: Data flow and interaction edge cases

```
  lesson.json ──▶ VALIDATE ──▶ CAPTURE ──▶ PROJECT ──▶ VERIFY ──▶ PACKAGE
     │              │            │            │           │           │
  [missing?]   [schema?]    [timeout?]   [overflow?]  [not-run?]  [partial dir?]
  [empty facts?][bad ref?]  [disagree?]  [font miss?] [flaky shot?][stale cache?]
```

Every shadow path has an error class from Section 2. Two more: a stale cache is prevented by content-hash keys, and a partial output dir is avoided by building into a temp dir and swapping it in atomically.

| Interaction | Edge case | Handled? | How |
|---|---|---|---|
| Explorer value input | non-integer, out of range, empty | Y | clamp and message; tested |
| Explorer bit toggles | keyboard only | Y | buttons with aria-pressed; tested |
| IVE pause-to-explore | pause mid-transition | Y | explorer loads the scene's settled state, never a tween value |
| IVE seek | seek past end / rapid scrubbing | Y | debounce; state = scene at time t |
| IVE | no JS | Y | static poster sequence + transcript |
| Video | autoplay with sound | Y | never; play is a user action |
| Cards | value with no printable glyph | Y | label "non-printable (code N)" |
| Q&A expander | open all at once / print | Y | details elements, print stylesheet expands all |

**D9.1.** IVE explorer state comes from scene states, never from in-between animation values. *Accepted*: it is exact by construction.

## Section 5: Code quality

- Keep one formatter for values, shared by all projectors, so the same fact can't render differently in two artifacts. That is DRY at the point that matters.
- No framework: templates are string templates with escaping. Over-engineering check: no plugin system for projectors in v2.1, since six fixed modules are enough.
- Branching budget: the router must not exceed 5 branches per function. Use a table-driven classifier with explicit rules plus tests, not regexes scattered through the code.
- **D10.1.** Table-driven router plus a dev prompt set of at least 60 prompts, kept separate from the holdout. *Accepted.*

## Section 7: Performance

- **Slowest paths.** Video render takes about 60–180 s, TTS about 1–2 s per sentence (cached), and Playwright screenshots about 5–10 s per artifact.

- **Cache.** TTS by content hash, captures by source hash plus compiler version.
- No issues beyond caching. **D12.1.** Caching *accepted.*

## Section 8: Observability

- `build-report.json` per lesson records every gate with status, measured values, thresholds, tool versions, durations and artifact paths. `ptk report` prints it as a table.

- Three weeks after a build, the report plus the logs reconstruct exactly what ran and which tool versions ran it.
- The "joy to operate" version: `ptk report --html` renders the build report with thumbnails of every artifact and gate.
- **D13.1** *Accepted.*

   198	## Section 1: Architecture
   199	
   200	```
   201	                         +------------------------- ptk (Python CLI) --------------------------+
   202	  request ──▶ route ──▶ | mode+medium+workspace contract ──▶ lesson.json (model)               |
   203	  (agent)               |                                    │  facts  claims  trace  storyboard |
   204	                        |   capture/c_runner ── clang,gcc-16 ┘                                   |
   205	                        |                                    ▼                                   |
   206	                        |  projectors: still │ explorer │ qa │ cards │ video │ ivideo          |
   207	                        |        │               │                    │         │               |
   208	                        |        ▼               ▼                    ▼         ▼               |
   209	                        |   SVG/PNG         HTML (self-contained)   HyperFrames  player page    |
   210	                        |                                           +Kokoro TTS  +state bridge  |
   211	                        |  gates: values · tamper · claims · contrast · screenshots · media     |
   212	                        |                     ▼                                                  |
   213	                        |            build-report.json (passed | failed | not-run)             |
   214	                        +-----------------------------------------------------------------------+
   215	  ported from v2: render_markdown (Node) · praxteach state+FSRS (optional) · tool registry (fixed)
   216	  external: clang · gcc-16 · node · playwright · hyperframes · kokoro venv · ffmpeg/ffprobe · manim (route only)
   217	```
   218	
   219	**Data flow and shadow paths (capture → model):**
   220	- **Happy path:** compile with both compilers, run twice, the outputs match, and they're stored as facts with sha256 hashes.
   221	- **Missing input** (no source or program for a fact): `ModelError("fact X has no source")`. The build stops.
   222	- **Empty stdout:** stored as an empty-string fact. Allowed, but a value gate that expects text fails loudly.
   223	- **Upstream error:**
   224	  - a compile error gives `CompileError` with the compiler's stderr;
   225	  - a timeout gives `RunTimeout`;
   226	  - outputs that differ between compilers give `CompilerDisagreement`, which is valid when the behaviour is implementation-defined, but then a claim must say so;
   227	  - outputs that differ between runs give `NondeterministicOutput`.
   228	
   229	**State machine (lesson build):**
   230	
   231	```
   232	  draft ──capture──▶ captured ──project──▶ projected ──verify──▶ verified ──package──▶ packaged
   233	    ▲                   │ fail                │ fail                │ any gate failed
   234	    └──── edit ◀────────┴─────────────────────┴─────────────────────┘ (stays failed; never "verified")
   235	  Invalid: projected→packaged without verify (ptk refuses); verified with a not-run gate marked passed (schema forbids).
   236	```
   237	
   238	**Coupling.**
   239	- Projectors depend only on `lesson.json` and the style tokens.
   240	- Gates depend on `lesson.json` and the artifacts, never on how a projector works internally.
   241	- The C repo isn't a dependency; the capture runner is self-contained.
   242	
   243	**Scaling.** A build costs one TTS pass per scene (cached) and one HyperFrames render, about 2–4 minutes for 60–90 s of video. Ten lessons in a pack cost about 30 minutes. The first thing to break at 10x is TTS and render time, so a content-hash cache and `--only` flags per projector handle it.
   244	
   245	**Single points of failure.**
   246	- The HyperFrames CLI, which auto-upgrades: the version is recorded in the report, and a `ptk host check` warns on drift.
   247	- The Kokoro venv: falls back to macOS `say`, disclosed in the report.
   248	- Playwright: if it's missing, the visual gate reports `not-run`.
   249	
   250	**Security architecture.** No network endpoints. The capture runner executes C that the agent wrote, so it gets a temp dir, rlimits, a timeout, process-group kill and no network (`sandbox-exec` profile where available, with the absence disclosed). Explorer and IVE HTML are self-contained, with a CSP meta tag that blocks all remote fetches.
   251	
   252	**Production failures per integration.**
   253	
   254	| Integration | Failure | Handled by |
   255	|---|---|---|
   256	| HyperFrames | Upgrades mid-build and changes lint rules | Version pin warning |
   257	| Kokoro | Long-path bug in its pronunciation data (seen today) | Venv setup applies the proven fix |
   258	| Playwright | Browser cache purged by an outside cleaner (seen on 2026-10-08) | `PLAYWRIGHT_BROWSERS_PATH` set to the package's own state dir |
   259

   218	
   219	**Data flow and shadow paths (capture → model):**
   220	- **Happy path:** compile with both compilers, run twice, the outputs match, and they're stored as facts with sha256 hashes.
   221	- **Missing input** (no source or program for a fact): `ModelError("fact X has no source")`. The build stops.
   222	- **Empty stdout:** stored as an empty-string fact. Allowed, but a value gate that expects text fails loudly.
   223	- **Upstream error:**
   224	  - a compile error gives `CompileError` with the compiler's stderr;
   225	  - a timeout gives `RunTimeout`;
   226	  - outputs that differ between compilers give `CompilerDisagreement`, which is valid when the behaviour is implementation-defined, but then a claim must say so;
   227	  - outputs that differ between runs give `NondeterministicOutput`.
   228	
   229	**State machine (lesson build):**
   230	
   231	```
   232	  draft ──capture──▶ captured ──project──▶ projected ──verify──▶ verified ──package──▶ packaged
   233	    ▲                   │ fail                │ fail                │ any gate failed
   234	    └──── edit ◀────────┴─────────────────────┴─────────────────────┘ (stays failed; never "verified")
   235	  Invalid: projected→packaged without verify (ptk refuses); verified with a not-run gate marked passed (schema forbids).
   236	```
   237

   239	- Projectors depend only on `lesson.json` and the style tokens.

1. **The plan dismisses its strongest strategic objection.** Zero logged practice sessions and MISSION’s warning become “raised once,” without changing priorities (§0A). **Fix:** deliver one requested lesson and observe a prediction→attempt→feedback session before generalizing. Measure use and friction; no learning-outcome claim is needed.

2. **The architecture comparison rigs the result.** Approach C is denied shared verification and interactive video without showing why either requires six custom projectors (§0C-bis). **Fix:** evaluate a thin coordinator with shared facts/checks, existing renderers, and an MP4 plus timestamp-to-state bridge. Require demonstrated limitations before building replacements.

3. **The hardest transformation is an unexplained arrow.** `request → lesson.json` has no authoring contract, implementation task, or quality test. Building two handcrafted JSON lessons proves rendering, not tutoring (§1, T9). **Fix:** specify who creates the model, required inputs, validation and repair; test an unfamiliar request through the installed skill.

4. **Compiler agreement is being mistaken for correctness.** Matching outputs do not establish defined C behaviour. Disagreement does not establish implementation-defined behaviour either (§1–2). **Fix:** add the undefined-behaviour guard promised in PLAN-INPUT, explicit platform assumptions, diagnostic/sanitizer checks, and independently justified expectations. Remove automatic “implementation-defined” rescue.

5. **The verifier can certify a consistently wrong lesson.** Projectors and gates consume the same model; sentence-to-claim mapping checks bookkeeping. Fixture reviewer outputs do not establish that the actual reviewer catches errors (§1, §6). **Fix:** test independent expected results and false claims inserted into otherwise valid models, using the real reviewer integration.

6. **Interactive correctness extends beyond captured examples.** A captured value of 66 does not validate every bit-toggle result or factorial state. “Settled state” can also reveal a future state when paused mid-transition (§4). **Fix:** define the interactive transition rules, permissible inputs and displayed state at each timestamp; check those against independent computations and prediction boundaries.

7. **Teaching modes are labels without a teaching protocol.** A table-driven router does not implement waiting, answer assessment, misconception feedback or resumption. Practice-log integration is deferred despite being part of the justification (§0A, WP1, §10). **Fix:** specify and test one complete multi-turn teaching exchange before adding more modes or porting FSRS.

8. **Mandatory acceptance dependencies remain unspecified.** The claims reviewer has no invocation/authentication contract; caption synchronization requires a transcriber whose availability is unresolved. Both must pass, while teach-time networking is restricted (§2, §6, FREEZE). **Fix:** prove both integrations offline or within explicitly approved access before implementing the projectors.

9. **“Deterministic” and “cached” are unsupported guarantees.** Recording an auto-upgrading CLI version does not pin it. Cache keys omit inputs such as compiler flags, included files, TTS engine/model versions and fallback engine (§0E, §1, §7). **Fix:** lock executable dependencies, key caches on complete effective inputs, and distinguish reproducible lesson data from reproducible media bytes.

10. **Sandbox policy contradicts itself.** D8.1 requires isolation; §1 permits its absence with disclosure. Resource limits and a temporary directory do not define filesystem confinement. **Fix:** specify denied filesystem/network capabilities, test them, and refuse capture when the required isolation is unavailable.

11. **Acceptance is underspecified for the claimed product.** Routing holdout improvement plus two known exemplars can pass while new lesson generation fails. “World-class” still lacks an executable decision rule (§6, §9, FREEZE). **Fix:** propose a versioned acceptance specification covering unfamiliar end-to-end requests, visual judgment criteria and baseline comparison. Obtain approval before changing the frozen evaluator.

12. **The stop rule does not control the actual project.** Nine packages allow up to 27 rounds; continuing after a foundational package stalls leaves downstream packages without prerequisites. The 6–10-hour estimate has no demonstrated basis (§Implementation Tasks, FREEZE). **Fix:** define dependencies, block dependent work after prerequisite failure, and propose a total budget before starting.

13. **Rollback covers code, not installed behaviour.** One symlink flip does not establish discovery across four hosts or undo shared learner-state writes. Candidate coexistence also needs reconciliation with “one entry per host” (§9, FREEZE). **Fix:** test host-specific install/rollback procedures and state compatibility; snapshot state before candidate writes.

## Changed protected behaviour

### Hard-linked learner-state files (D22.3, round 17, 2026-10-18; replaces the round-15 integration-pass change)

**Status: pending Prax's approval.** Ordered by the orchestrator (PROGRESS D22.3) after the round-17 gates audit (P2-1) and Codex review (item 3) showed the round-15 change let one learner's state be read and exported as another's.

- **What changed.** v2 refused any state file, journal or workspace lock with `st_nlink != 1`. Round 15 accepted any extra link on a regular file owned by the effective user. Now learner state binds content, not link counts:
  - Each workspace's `state/` directory carries a random learner binding (`lw-` + 32 hex) in the extended attribute `user.praxteach.learner`, created once at `init` (or, for older workspaces, on the first command, race-safe with create-only).
  - Every file the engine writes carries the same binding on its inode. It is stamped on the fresh temporary file before the rename, so it is atomic with the write.
  - A hard link shares its inode, so it shares the binding. An extra link is read, with the `HardlinkAccepted` warning, only when the file is a regular file this user owns and its binding equals the state directory's. A file bound to another workspace is refused (exit 5), whatever its link count. Directories cannot be hard-linked, so the directory's binding cannot be aliased the same way.
  - Writes: every write path (`atomic_write`, `atomic_write_anchored`, `append_jsonl`, `make_private_file`, export, rollback) lands on a fresh inode: an exclusive temporary file, fsync, then rename over the name. No write goes through an alias.
  - Locks: a missing workspace lock is created with `O_EXCL` (fresh inode, bound). An existing lock is checked by path before it is opened, and again on the descriptor. It is never written on POSIX (flock only).
  - The full-deletion journal sits outside every state directory. Its content already names the exact workspace path and inode it deletes, so an extra link to it is read when an engine write stamped it (any binding).
  - Code: `ptk/state/io.py` (`link_problem`, `ensure_binding`, `stamp_binding`, `read_binding`, `secure_workspace`, `read_bytes`, `_workspace_inode_lock`, the write primitives), `state.py` (journals, `init`), `continuity.py`, and the new `rebind.py` with `python -m ptk.state rebind`.
- **Migration for files written by older code (no binding).** With one link, the file is read and stamped on the first command that touches it. It has no other name, so it can only be this workspace's. Bytes never change. An unbound file that already has an extra link is refused (exit 5) with a message naming `rebind`. `python -m ptk.state rebind <workspace>` lists such files (exit 4). With `--confirm`, it copies each one onto a fresh, bound inode and leaves the old inode and its other names untouched. It never rebinds a file that carries another workspace's binding and still has another link: that link must be removed by hand.
- **Why.** The macOS backupd/revisiond links (new files under `~/Developer` and Prax's C study workspace get `st_nlink` 2 within seconds, same inode) are links to the learner's own file. They carry its binding and keep working. A link from learner B's workspace carries B's binding and is refused, as v2 required. Embedding the id in file bytes was rejected: it would change on-disk and exported bytes, the v1 fixture digests, and about 60 lines in the ported v2 tests that read or write state files directly.
- **Tests.**
  - Restored to the v2 bytes: `test_state_security::test_required_state_hardlink_cannot_cross_learner_boundaries` (show and export exit 5, no export file) and `test_continuity_security::test_unsafe_optional_records_fail_all_controls` (hardlink subcase exit 5). `test_workspace_lock_rejects_hardlinks_without_chmodding_the_source` passes unchanged. All 106 ported tests run with no assertion changed from v2.
  - New in `tests/test_state.py`: `test_cross_learner_hardlink_refused` (B's sessions.jsonl and B's lock linked into A: exit 5, no export, B unchanged; both learners share a learner id), `test_backup_link_to_own_file_reads_with_warning`, `test_write_never_goes_through_an_alias` (the outside alias keeps the old bytes, and the workspace file is a new inode), `test_backup_link_to_delete_journal_recovers`, `test_legacy_unbound_state_migrates` (adoption, refusal, `rebind` preview and confirm), and `test_symlinked_and_foreign_state_refused` (now adopts first, then checks the foreign owner, symlink and FIFO cases).
- **Residual risk.**
  - Where the filesystem has no extended attributes (Linux tmpfs before kernel 6.6, Windows), nothing is bound and v2's rule applies: any extra link is refused. On macOS volumes that emulate attributes (exFAT, FAT, SMB), the OS may create `._` sidecar files.
  - The binding is a label the same user can read and copy with `xattr`. It stops accidental and tool-made aliasing across learners, not a same-user attacker, who can copy files anyway.
  - A workspace copied with its attributes (`cp -R` on macOS, Finder) keeps the same binding, so links between the original and the copy are read. Both hold the same learner's data.
  - Read-only commands now write metadata: a missing directory binding, and stamps on single-link legacy files. Learner bytes never change, and that includes workspaces whose persistence consent is withdrawn.

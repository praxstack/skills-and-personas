For a tutor the product is the *verified lesson model*, and renders are cheap projections of it. One model with facts, claims, a trace and a storyboard fixes correctness, consistency across artifacts, and interactive video, all at once. Interactive video stops being a special feature: it is the video and the explorer projected from the same state timeline.

## Step 0

### 0A. Premise challenge

1. **Is this the right problem?**
   - The literal problem, "make v2 produce six artifact types well", is right but framed too low.
   - The real problem is that v2 has no single source of truth. It verifies files, not facts, and it routes by keywords, not by intent and the workspace's own contract.
   - So patching v2 means 114 local fixes. Restructuring around a lesson model removes whole classes of them.
2. **The actual outcome.** Prax learns C, then C++, DSA and GATE CS from explanations that are never wrong and look world-class, in the medium he asks for, inside his own study loop: a prediction first, the attempt log, spaced review.
3. **If we do nothing.**
   - v2 keeps routing "narrated video" requests to text-only answers.
   - It can't hold a video.
   - It ships wrong figures with "passed" receipts.
   - It also contradicts the workspace's Socratic contract.

   That is real pain, observed today, not hypothetical.
4. **Raised once and recorded, not re-argued.** `MISSION.md` in the C workspace warns against replacing practice with an expanding curriculum or dashboard, and that workspace has zero practice sessions logged. This plan is tooling. Prax chose to keep improving tooling, and this plan honours that choice in two ways:
   - **Build requirement:** the tool must make practice easier, not replace it. Prediction-first mode, cards wired to his spaced review, and exam drills are all in scope.
   - **Dogfooding requirement:** both exemplar lessons are C topics he needs anyway.

## Round 1 revisions (binding; they override earlier text where the two conflict)

Cross-model tension was resolved autonomously, as Prax asked. Each D17 item records which reviewer raised it and why it was accepted. None of these items changes FREEZE.md.

**D17.1 Vertical slice first** (Codex 1, 12; reviewer 9).
- **Before generalising, build WP0.** One unfamiliar request goes through the real skill entry → `lesson.json` → all six artifacts → every gate, for one lesson.
- **Dependency order:** WP0 → (WP1 ∥ WP2) → WP3 → WP4 → WP5 → WP6 → WP7 → WP8 → WP9.
- **If a package stalls, its dependents stop.**
- **Total budget:** 18 implement-and-review rounds across all packages. This is stricter than FREEZE's maximum of 27, so it is a self-limit, not a gate change.
- **A live session is a human step.** One real prediction → attempt → feedback session with Prax is listed as a human acceptance step, like the Competitive Companion click. The agent can't run it alone.

**D17.2 Interactive video design** (Codex 2, reviewer 6). The IVE is the narrated MP4 plus a WebVTT `metadata` cue track.
- Each cue carries `{scene_id, state_id}`.
- On pause, seek or chapter jump, the page loads the explorer at that cue's state, which is the last state already shown (D18.2).
- It works for any video source, HyperFrames or Manim. No in-page composition runtime is needed.

**D17.3 Authoring contract** (Codex 3; reviewer 9).
- **Writing the model:** the host agent writes `lesson.json` from `references/LESSON-MODEL.md`, using `ptk new <slug>` to scaffold. `ptk validate` reports JSON-pointer errors, and the agent repairs at most twice per error.
- **Runtime flow per mode:**
  - **Quick answer:** the agent answers directly. No model and no build.
  - **Predict-first:** one question, wait, then feedback. Artifacts come only after the attempt.
  - **Lesson in a named medium:** model → capture → the projectors for the requested media only → gates → deliver. The agent tells the learner first whether the build will take more than 60 s.
  - **Full pack:** only when asked.
- **The router is code** (`ptk route`). SKILL.md tells the agent to call it and obey its result.

**D17.4 Undefined-behaviour guard and platform facts** (Codex 4; reviewer 1, 14).
- **Compiler flags:** capture compiles with `-std=c17 -Wall -Wextra -Wformat=2 -fsanitize=undefined,address`. Any warning or sanitizer report blocks the fact, unless a claim of kind `undefined-behaviour` covers it, and such programs are compiled but never run.
- **Platform facts are captured once and shown wherever relevant:** `sizeof` of each scalar, char signedness, endianness, libc.
- **CompilerDisagreement is never rescued automatically.** It fails unless an authored claim of kind `implementation-defined` cites the C standard clause.
- **Two compilers don't add trust here.** clang and gcc-16 share Apple's libc on this Mac, so comparing them doesn't make printf output more trustworthy. The claim is dropped. The second compiler only checks diagnostics.

**D17.5 Independent expectations and mutation testing** (Codex 5, 6; reviewer 1).
- Every displayed fact needs an independent `expect` field, computed by a separate Python function (bits, ASCII, arithmetic) or authored and reviewed.
- The values gate compares the artifact against both the capture and the expectation.
- **Mutation suite:** for each lesson, a script makes 10 or more corrupted variants (false claims, swapped values) and runs the *real* claims reviewer and value gates. At least 90% must be caught, and every value mutation must be.
- **Explorer logic:** checked against an independent computation over its whole input domain.
- **No spoilers:** a paused state never shows the answer to an open prediction question (retrieval safety, M20). That covers narration, transcript, chapter titles and alt text.

**D17.6 Teaching protocol** (Codex 7; reviewer 1).
- **Multi-turn spec:** `references/TEACHING.md` defines predict-first as a multi-turn protocol:
  1. ask one question;
  2. end the turn;
  3. classify the attempt as correct, partial or misconception;
  4. give exactly one hint or feedback;
  5. show the artifact;
  6. record evidence (recognition, recall, explain, apply).
- **Transcript test:** `tests/test_protocol_transcripts.py` drives it with scripted learner turns.
- **Workspace contract precedence:** AGENTS.md, MISSION.md and NOTES.md are read first, and their rules beat skill defaults.
- **Hidden end state:** traces hide the final state until the learner predicts (fixes T3).
- **Evidence:** stored in `.prax-teach/state` as `evidence` events, with consent. T2 is answered by the stop rule "satisfaction plus at least one observed evidence item, or an explicit stop".

**D17.7 Claims reviewer contract** (Codex 8; reviewer 8).
- **Who reviews:** the host agent spawns a separate subagent with a fixed rubric and the lesson's claims, sources and artifact texts. It writes `claims-review.json`, and `ptk claims check` validates its schema.
- **Coverage:** every sentence in narration, captions, labels, cards, Q&A and the still must carry a claim ID, tagged by the author in the storyboard or model and checked by `ptk`.
- **Not run is not passed:** if no subagent facility exists in the host, the gate is `not-run` and the build is `incomplete`. It is never `passed`.

**D17.8 Offline caption sync** (Codex 8; reviewer 4).
- The sync gate uses `whisper-cli`, which is already installed, with a local ggml model under `$PTK_STATE/models`. `hyperframes transcribe` is the second choice.
- **Pass rule:** every cue start within 0.5 s of its planned time, and word error rate on non-code words of 10% or less.

**D17.9 Pinned and reproducible builds** (Codex 9; reviewer 10, 13).
- **Pinned HyperFrames:** a local npm install inside `$PTK_STATE/tools` at a pinned version, never the global auto-upgrading CLI.
- **Cache keys:** the full effective inputs (source bytes, includes, flags, compiler version, TTS engine, model file sha256, voice, speed, lexicon version and fallback engine).
- **What reproducibility means:** "reproducible" applies to the lesson data and the HTML/SVG bytes. Media bytes are checked against tolerances instead.
- **No silent fetches:** outbound network during render is blocked by the sandbox profile in D18.3, and any denied request fails the build.

**D17.10 Sandbox** (Codex 10; reviewer 14).

- **No sandbox, no capture:** if `sandbox-exec` is missing, `ptk` refuses to capture. There is no silent fallback.

## Round 2 revisions (binding)

Round 2 scored the plan 7/10 with 11 issues. All 11 are accepted.

**D18.1 Claims handoff state.** The build gains a `claims-pending` state.
1. `ptk verify` runs every automatic gate.
2. It writes `build/<lesson>/claims-jobs/*.json`: one job for the lesson, plus one per mutation. Mutations are capped at 12 per lesson.
3. The host agent runs each job in a separate subagent and writes `claims-review/*.json`.
4. `ptk claims check` validates the reviews and finishes the build.

The mutation suite uses this same path.

```
  draft ─capture─▶ captured ─project─▶ projected ─verify─▶ claims-pending ─claims check─▶ verified ─package─▶ packaged
                                                                  │                          │
                                                                  └── reviews missing ──▶ incomplete    any gate failed ──▶ failed
  Final statuses: verified | degraded (all gates passed but a fallback was used, e.g. `say` TTS; not verified) | incomplete (a gate not-run) | failed
```

**D18.2 No answer leaks on pause.**
- A cue's state is the last state already shown on screen, never the settled end of a transition that is still running.
- Every reveal becomes two cues: a question cue, with the state before the answer, and an answer cue.
- Pausing on a question cue shows the question state only.
- A test pauses at 0.1 s before each answer cue and checks that no answer text appears in the DOM, the alt text or the transcript shown so far.

**D18.3 Render network block.**
- `hyperframes render` and `check` run under a `sandbox-exec` profile that denies all network except loopback. They have no request hook of their own.
- Any denied request appears in the render log, and the build then fails.
- Moved into the T0 spikes.

## Section 1: Architecture

```
                         +------------------------- ptk (Python CLI) --------------------------+
  request ──▶ route ──▶ | mode+medium+workspace contract ──▶ lesson.json (model)               |
  (agent)               |                                    │  facts  claims  trace  storyboard |
                        |   capture/c_runner ── clang,gcc-16 ┘                                   |
                        |                                    ▼                                   |
                        |  projectors: still │ explorer │ qa │ cards │ video │ ivideo          |
                        |        │               │                    │         │               |
                        |        ▼               ▼                    ▼         ▼               |
                        |   SVG/PNG         HTML (self-contained)   HyperFrames  player page    |
                        |                                           +Kokoro TTS  +state bridge  |
                        |  gates: values · tamper · claims · contrast · screenshots · media     |
                        |                     ▼                                                  |
                        |            build-report.json (passed | failed | not-run)             |
                        +-----------------------------------------------------------------------+
  ported from v2: render_markdown (Node) · praxteach state+FSRS (optional) · tool registry (fixed)
  external: clang · gcc-16 · node · playwright · hyperframes · kokoro venv · ffmpeg/ffprobe · manim (route only)
```

**Data flow and shadow paths (capture → model):**
- **Happy path:** compile with clang under the sandbox with warnings and sanitizers on (D17.4), run twice, the outputs match, and they're stored as facts with sha256 hashes next to the independent `expect` values. gcc-16 compiles the same source for diagnostics only.
- **Missing input** (no source or program for a fact): `ModelError("fact X has no source")`. The build stops.
- **Empty stdout:** stored as an empty-string fact. Allowed, but a value gate that expects text fails loudly.
- **Upstream error:**
  - a compile error gives `CompileError` with the compiler's stderr;
  - a timeout gives `RunTimeout`;
  - outputs that differ between compilers give `CompilerDisagreement`, which is valid when the behaviour is implementation-defined, but then a claim must say so;
  - outputs that differ between runs give `NondeterministicOutput`.

**State machine (lesson build):**

```
  draft ──capture──▶ captured ──project──▶ projected ──verify──▶ claims-pending ──claims check──▶ verified ──package──▶ packaged
    ▲                   │ fail                │ fail                │ any gate failed
    └──── edit ◀────────┴─────────────────────┴─────────────────────┘ (stays failed; never "verified")
  Invalid: projected→packaged without verify (ptk refuses); verified with a not-run gate marked passed (schema forbids).
```

**Coupling.**
- Projectors depend only on `lesson.json` and the style tokens.
- Gates depend on `lesson.json` and the artifacts, never on how a projector works internally.
- The C repo isn't a dependency; the capture runner is self-contained.

**Scaling.** A build costs one TTS pass per scene (cached) and one HyperFrames render, about 2–4 minutes for 60–90 s of video. Ten lessons in a pack cost about 30 minutes. The first thing to break at 10x is TTS and render time, so a content-hash cache and `--only` flags per projector handle it.

**Single points of failure.**
- HyperFrames: a pinned local install (D17.9). If it's missing, video gates are `not-run` and the build is `incomplete`.
- The Kokoro venv: falls back to macOS `say`, disclosed in the report.
- Playwright: if it's missing, the visual gate reports `not-run`.

**Security architecture.** No network endpoints. The capture runner executes C that the agent wrote, so it gets a temp dir, rlimits, a timeout, process-group kill, a resident-size watchdog and a tested `sandbox-exec` profile (no network, no writes outside the temp dir). If `sandbox-exec` is missing, capture refuses to run (D17.10). Explorer and IVE HTML are self-contained, with a CSP meta tag that blocks all remote fetches.

**Production failures per integration.**

| Integration | Failure | Handled by |
|---|---|---|
| HyperFrames | Global CLI upgrades itself mid-build (seen today) | Pinned local install (D17.9); the global CLI is never used |
| Kokoro | Long-path bug in its pronunciation data (seen today) | Venv setup applies the proven fix |
| Playwright | Browser cache purged by an outside cleaner (seen on 2026-10-08) | `PLAYWRIGHT_BROWSERS_PATH` set to the package's own state dir |

**Rollback.** v2.1 installs alongside v2 under a candidate name. Acceptance flips the `prax-teach-v2` symlink, and rollback flips it back: one command, about 1 second.

**Beautiful version.** One file, the lesson model, is the only thing an author writes. Everything else is a pure function of it, plus captured runs. A new engineer reads `lesson.schema.json` and the six projector files and understands the whole system.

**Platform potential.** Topic packs (Phase 2), a cpx integration that cards and drills feed into, and other learners' workspaces.

Section 1 decisions:
- **D6.1** Per-scene HyperFrames sub-compositions. *Accepted*, completeness 10 versus 7 for one file, because it fixes the proof's lint warnings.
- **D6.2** The capture runner is self-contained rather than importing cpx. *Accepted*: separate products and no cross-repo coupling.

### Outside voice

Codex ran on the full plan including this section. Its findings are in `plan/outside-voice-codex-eng.md` and are dispositioned below.

Codex raised 12 findings. All are accepted, as autonomous decisions E14–E25. There's no tension left, because each finding adds a missing check rather than contradicting a decision.

**E14. Complete offline inventory.** `ptk host setup` pins and fetches each of these:
- the Playwright Chromium revision into `$PTK_STATE/browsers`;
- HyperFrames' Chrome into its pinned cache, through `hyperframes browser` with the cache dir set inside `$PTK_STATE`;
- the Kokoro `.onnx` model and voices file, with sha256;
- the whisper model;
- the HyperFrames Docker image, only if the E1 fallback is used.

The test is a first build run with an empty `HOME` and no network that ends `verified`.

**E15. Update checks off.** The env always sets `HYPERFRAMES_NO_UPDATE_CHECK=1`. A test runs the pinned 0.8.169 offline and checks that its install dir hash doesn't change.

**E16. Proving network isolation.** ET1 needs canaries that fail where we can see them: a DNS lookup, an HTTPS fetch, and a child process that tries to connect. All three must fail inside the render environment. The Docker fallback is exactly `docker run --rm --network none -v <proj>:/w <pinned image> hyperframes render ...`, plus the same canaries.

**E17. Caption timing against the actual audio.**
- Measure each synthesised segment's duration first, and schedule cues from those measurements.
- The sync gate compares speech start *and end* timestamps from whisper run on the final MP4 against the VTT cue starts and ends, within 0.5 s.
- Fixtures: shifted audio, truncated speech, and a mispronounced code token. Each must fail.

**E18. Claims reviews bound to their inputs.**
- Each claims job carries a manifest: sha256 of the lesson model, every artifact text, the sources and the rubric version.
- Each review must echo that manifest hash, and any edit invalidates the reviews it affects.
- Test: replay an old passing review against changed content, and it must be rejected.

**E19. Separate sanitizer fixtures.** Four separate fixtures:
- a format-warning one (`printf("%f", a)` caught by `-Wformat`);
- runtime ASan (heap overflow);
- runtime UBSan (signed overflow);
- a gcc-16 diagnostics-only command.

Clean sanitizer output is recorded as "no finding", never "no UB". The UB claim kind is still required for any UB topic.

**E20. CSP that actually works.** Every self-contained HTML file gets `default-src 'none'; script-src 'sha256-…'; style-src 'sha256-…'; img-src data:; media-src 'self'; font-src data:; track-src 'self'`. That is, `media-src`, also covering track loading, with hashes computed at build time. The Playwright tests run with this CSP enforced, on the packaged files.

**E21. Who runs the subagents.** `ptk selftest` covers every automatic check. The agent-mediated tests (real claims reviews, teaching transcripts) form a separate suite, `ptk agent-tests`, which writes jobs, stops at `claims-pending` (exit 4), and resumes with `ptk claims check`. `references/HOST-ADAPTERS.md` describes the subagent invocation for each host (Claude Code: Agent tool; Codex: `codex exec`; Hermes and OpenCode: their subagent commands). Both suites are run on each supported host.

**E22. Mutation controls.**
- Every mutation is paired with an unchanged control.
- At least 95% of controls must be accepted, alongside the mutation catch rates.
- A schema rejection is counted separately from detecting the intended error.

**E23. Real Anki import test.** Open the `.apkg` (zip plus SQLite), check the note fields, stable GUIDs and media. Then import into an isolated Anki profile with the Anki CLI or `anki` package if present, or else mark that step `not-run`. Re-importing must not create duplicates.

**E24. Capture resource limits.**
- Capture programs may not create child processes: the sandbox denies `process-fork` except for the runner itself.
- stdout and stderr are capped at 1 MB, with truncation turning into a failure.
- Memory is capped across the whole process group.
- A test checks cleanup after a timeout and after a watchdog kill.

**E25. Write boundary.** E10 is revised. The test plan lives only in `plan/TEST-PLAN.md`, and the earlier copies under `~/.gstack/projects/v2.1/` were deleted. The gstack review logs and the decision log still write to `~/.gstack`, because the review skills require them. They are workflow metadata, not candidate files, and are disclosed here.
